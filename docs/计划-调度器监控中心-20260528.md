# 调度器监控中心 — 实施计划

## Context

项目有 4 个 Scheduler 类共 16 个定时任务，运行时没有任何监控/追踪。用户要求在**站点设置页面**（`/admin/settings`）里嵌入调度器监控面板，列出所有后台进程的作用说明、状态，支持手动触发。

## 设计决策

- **跟踪机制**：新建 `SchedulerTaskTracker`（Service，ConcurrentHashMap 记录），各 Scheduler 用 try/catch 包裹，调用 tracker。
- **端点**：扩展 `MonitorController`，新增 scheduler 接口。
- **前端位置**：直接在现有 `views/admin/settings/index.vue` 页面底部加一个 `<el-card>` 区域，不新建路由、不新建页面。
- **手动触发**：反射 `ApplicationContext.getBean().method()` 实现。

## 实施步骤

### 1. 后端 — 新建 SchedulerTaskTracker

**文件**：`backend/dataagg-start/src/main/java/com/dataagg/start/service/SchedulerTaskTracker.java`

```java
@Component
public class SchedulerTaskTracker {
    // ConcurrentHashMap<String, TaskStatus> tasks — 16个任务状态
    // ConcurrentHashMap<String, Runnable> registry — 手动触发注册表
    
    // 内部类 TaskStatus: taskId, name, description, group,
    //   triggerType(CRON/FIXED_DELAY), triggerValue,
    //   status(IDLE/RUNNING/SUCCESS/FAILED),
    //   lastStartTime, lastEndTime, duration, errorMessage,
    //   executionCount, totalFailures
    
    // register(taskId, name, desc, group, triggerType, triggerValue, runnable)
    // markRunning / markSuccess / markFailed(taskId, error)
    // getAllStatuses() → List<TaskStatus>（按group排序）
    // trigger(taskId) → CompletableFuture.runAsync(runnable)
}
```

### 2. 后端 — 改造 4 个 Scheduler

每个方法包裹 tracker，添加 `@PostConstruct` 注册元数据。

**StockDataScheduler**（13个方法）：全部包裹 + postConstruct 注册。为简洁，抽取 wrap 方法：
```java
private void wrap(String id, String name, String desc, String triggerType, 
                  String triggerVal, Runnable task) {
    tracker.register(...);
    // 原方法改为一行: wrap("pollIndices", "指数行情", "拉取三大指数...",
    //   "FIXED_DELAY", "30s", () -> stockDataService.fetchAndCacheIndices());
}
```

但 @Scheduled 方法必须是 public no-arg，所以保留原方法签名，在体内调用 tracker。

### 3. 后端 — MonitorController 新增端点

```java
@Autowired private SchedulerTaskTracker schedulerTracker;

@GetMapping("/monitor/schedulers")
@RequireAuth("ADMIN")
public Result<List<Map<String,Object>>> listSchedulers() {
    return Result.success(schedulerTracker.getAllStatuses());
}

@PostMapping("/monitor/scheduler/{taskId}/trigger")
@RequireAuth("ADMIN")
public Result<Void> triggerScheduler(@PathVariable String taskId) { ... }
```

### 4. 前端 — API 层（monitor.ts）

新增 `TaskStatus` 接口 + `getSchedulerTasks()` + `triggerSchedulerTask(taskId)`。

### 5. 前端 — 站点设置页嵌入

**修改** `views/admin/settings/index.vue`：

在 `</div>` (settings-content) 之前、最后一个 `</el-card>` 之后，新增一个 `<el-card>` 区块：

```html
<el-card class="group-card">
  <template #header>
    <div class="group-header">
      <span class="group-title">调度器监控</span>
      <el-button size="small" @click="loadSchedulers" :loading="schedulerLoading">
        <el-icon><Refresh /></el-icon> 刷新
      </el-button>
    </div>
  </template>
  <el-table :data="schedulerTasks" stripe size="small" v-loading="schedulerLoading">
    <el-table-column prop="name" label="任务名称" width="140" />
    <el-table-column prop="description" label="说明" min-width="200" />
    <el-table-column label="触发" width="130">
      <template #default="{ row }">
        <el-tag size="small" :type="row.triggerType==='CRON'?'':'info'">{{ row.triggerType }}</el-tag>
        <span style="margin-left:4px;font-size:12px;color:#999">{{ row.triggerValue }}</span>

      <template #default="{ row }">
        <el-tag size="small" :type="statusType(row.status)">{{ row.status }}</el-tag>
      </template>
    </el-table-column>
    <el-table-column label="上次运行" width="150">
      <template #default="{ row }">{{ row.lastStartTime || '-' }}</template>
    </el-table-column>
    <el-table-column label="耗时" width="80">
      <template #default="{ row }">{{ row.duration || '-' }}</template>
    </el-table-column>
    <el-table-column label="执行/失败" width="90">
      <template #default="{ row }">{{ row.executionCount }}/{{ row.totalFailures }}</template>

```

script 中新增：

## 验证

1. `curl -H "Authorization: Bearer <admin-token>" http://localhost:8081/api/admin/monitor/schedulers` — 返回 16 个 IDLE 任务
2. 等 30s 后再次请求 — pollIndices 状态变为 SUCCESS
3. POST trigger 手动触发 — 正常执行并更新状态
4. 前端打开 `/admin/settings` — 底部看到调度器表格，自动刷新
