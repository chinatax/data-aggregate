# 博客性能优化计划

## Context
博客页面打开慢，三份探查报告（前端代码、后端代码、构建产物）汇总发现：每次博客列表页命中 10-20 次数据库查询（N+1），缓存因 view count 递增而每次被踢失效，前端 JS/CSS 打包后 2.4MB 未经压缩传输，Element Plus 和 highlight.js 全量导入。这些都是明显可修复的性能瓶颈。

## Overview
- **Phase 1**：快速见效（单文件改动，低风险，极高 ROI）— gzip、缓存修复、列表排除 content 字段、封面懒加载
- **Phase 2**：核心优化（多文件，中高努力，最大累积收益）— 批量查询替代 N+1、Element Plus 按需引入、Vite manualChunks、highlight.js 裁剪
- **Phase 3**：深度优化（部署涉及、努力较高、增量收益）— 数据库索引、keep-alive、异步浏览计数、图片转 WebP

---

## Phase 1：快速见效（预计 1-2 小时）

### 1.1 修复缓存失效 — 取消 view count 时踢除列表缓存
**文件**: `BlogController.java` getById 方法 (~line 163)
- **问题**: 每次浏览文章都调用 `cache.evictAll("blogPages")`，列表页缓存从未命中
- **修改**: 删除 `cache.evictAll("blogPages");`，只保留 `cache.evict("blogs", id);`
- **影响**: 列表页缓存真正生效，重复访问快 10-100x

### 1.2 Nginx 开启 gzip 压缩
**文件**: `docker/nginx/nginx.conf`
- **问题**: 1.2MB JS + 1.2MB CSS 未经压缩传输
- **修改**: 在 server 块加 `gzip on; gzip_comp_level 6; gzip_types text/plain text/css application/json application/javascript ...;`
- **影响**: 传输体积减少 ~70%，首屏加载少 2-4 秒

### 1.3 列表查询排除 content 大字段
**文件**: `BlogService.java` pageByCondition 方法 (~line 16)
- **问题**: `SELECT *` 查出 LONGTEXT 文章正文，列表完全不用
- **修改**: `wrapper.select(Blog.class, info -> !"content".equals(info.getColumn()));`
- **影响**: 列表页 DB→应用→JSON 传输量大幅减少

### 1.4 封面图片懒加载
**文件**: `frontend/src/views/blog/index.vue` (~line 142)
- **修改**: `<img>` 加 `loading="lazy" decoding="async"`
- **影响**: 视口外封面不抢占带宽

### 1.5 合并 detail.vue 双重 Markdown 解析
**文件**: `frontend/src/views/blog/detail.vue`
- **问题**: `renderedContent` 用 markdown-it 渲染，`tocItems` 用独立正则重新扫描原文
- **修改**: 在 markdown-it 的 heading_open 渲染器中收集标题到一个数组，`tocItems` 直接读这个数组，不再单独正则
- **影响**: 单页 markdown 处理时间减半

## Phase 2：核心优化（预计 3-5 小时）

### 2.1 批量查询 resolveAuthorAvatars（消除 N+1）
**文件**: `BlogController.java` + `UserService.java`
- **问题**: 循环对每个 blog 单独查 user 表
- **修改**: 收集所有 author → 一次 `WHERE username IN (...)` → Map 赋值
- **影响**: 列表页从 N+1 变 2 次查询

### 2.2 批量查询 resolveFavorites（消除 N+1）
**文件**: `BlogController.java` + `BlogFavoriteService.java` + `BlogFavoriteMapper.java`
- **问题**: 循环对每个 blog 单独 COUNT 收藏数
- **修改**: 新增 Mapper 方法 `SELECT blog_id, COUNT(*) FROM blog_favorite WHERE blog_id IN (...) GROUP BY blog_id`
- **影响**: 收藏计数从 N 次变为 1 次

### 2.3 Element Plus 按需引入
**文件**: `frontend/src/main.ts` + `frontend/vite.config.ts` + `frontend/package.json`
- **问题**: 全量导入 Element Plus（~1.2MB CSS + ~500KB JS）
- **修改**: 安装 `unplugin-vue-components` + `unplugin-element-plus`，在 vite.config.ts 配置 ElementPlusResolver，main.ts 删除全局注册
- **影响**: CSS 减少 60-80%，每个路由块不再重复 400KB Element 主题

### 2.4 Vite manualChunks 分包
**文件**: `frontend/vite.config.ts`
- **修改**: 添加 `build.rollupOptions.output.manualChunks`：
  - `vue-vendor`: vue, vue-router, pinia
  - `element-plus`: element-plus
  - `markdown`: markdown-it, highlight.js
- **影响**: 并行下载，vendor 缓存命中率更高

### 2.5 highlight.js 裁剪为 common 包
**文件**: `frontend/src/views/blog/detail.vue` + `frontend/src/views/blog/editor/index.vue`
- **问题**: `import hljs from 'highlight.js'` 全量导入 ~300KB
- **修改**: 改为 `import hljs from 'highlight.js/lib/common'`（约 35 种常用语言，~100KB）
- **影响**: 减少 ~200KB

### 2.6 修复 MultiLevelCache.evictAll KEYS * 阻塞
**文件**: `MultiLevelCache.java`
- **问题**: `redis.keys(pattern)` O(N) 阻塞 Redis
- **修改**: 改用 `ScanOptions` + cursor 遍历
- **注意**: Phase 1.1 已移除热路径上的 evictAll 调用，此问题降级

### 2.7 BlogController.categories 加缓存
**文件**: `BlogController.java`
- **问题**: BlogController 的 categories 端点未缓存（CategoryController 的有缓存）
- **修改**: 用 MultiLevelCache 包装，TLL 60min（与 CategoryController 一致）

## Phase 3：深度优化（预计 2-4 小时）

### 3.1 数据库索引
**新建文件**: SQL 迁移脚本
- 复合索引: `blog(deleted, status, category, create_time)`
- FULLTEXT 索引: `blog(title, summary, tags)`（中文需 ngram parser）
- 索引: `blog_favorite(blog_id)`, `blog_favorite(user_id)`, `comment(blog_id, parent_id)`
- **影响**: 列表查询、关键词搜索提速明显

### 3.2 博客列表 keep-alive 缓存
**文件**: `frontend/src/layout/index.vue` + `frontend/src/views/blog/index.vue`
- **问题**: 列表→详情→返回，列表组件重新挂载、重新请求
- **修改**: keep-alive include 加上 BlogList 组件名

### 3.3 浏览计数异步化
**文件**: `BlogController.java`
- **问题**: 每次浏览同步 UPDATE db，阻塞响应
- **修改**: `redis.opsForValue().increment("view_count:" + id)` + 定时任务批量刷 DB

### 3.4 图片转 WebP
- 转换 `tax-theory-cover.png`(435KB)、`wechat-qr.png`(167KB)、`alipay-qr.jpg`(239KB) → WebP
- 实现真正的 `coverThumb` 缩略图（加 ?width=400 参数或 OSS 处理）

### 3.5 资源预加载提示
**文件**: `frontend/index.html`
- 添加 `dns-prefetch` 到 API 域名、`modulepreload` 到关键 chunk
